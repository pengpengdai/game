# 打字比赛小游戏 · 功能扩展与服务端技术方案

> 版本：v1.0 ｜ 状态：待评审 ｜ 范围：邀请好友对战 / 激励视频复活 / 音效 / 好友排行榜 + 服务端
> 说明：本方案只做设计，不改动现有 `typing-race/` 客户端代码。

---

## 1. 背景与目标

### 1.1 现状
已交付纯前端单机版（抖音 `tt.*` / 快手 `ks.*` 自动适配）：与 AI 竞速打字、中英文双题库、三档难度、段位计分、本地最高分。无网络、无音频、无广告、无社交能力。

### 1.2 本期目标
| 功能 | 一句话定义 | 是否需要服务端 |
|------|-----------|--------------|
| ① 邀请好友比赛 | 房主分享卡片，好友点开进入同一房间实时对战 | **需要**（房间/同步/结算） |
| ② 激励视频复活 | 失败看广告复活或减速对手，服务端限频防刷 | 需要（限次校验，进阶回调验签） |
| ③ 音效 | 背景音乐 + 击键/错误/胜利音效 + 震动 | 不需要（纯客户端） |
| ④ 好友排行榜 | 好友速度榜（开放数据域）+ 全局榜（服务端，二期） | 好友榜免服务端，全局榜需要 |

### 1.3 设计原则
1. **双端同构**：所有平台差异继续收敛在 `js/platform.js`，业务代码不出现 `tt`/`ks` 字样。
2. **增量迭代**：音效 → 复活 → 好友榜 → 服务端 → 实时对战，每步可独立上线。
3. **MVP 务实**：对局同步采用"客户端打字、服务端转发进度 + 阈值校验"，不做服务端逐字符权威判定（成本高、延迟大）。
4. **跨端互通**：服务端房间支持抖音玩家与快手玩家同场对战（同一 userId 体系）。

## 2. 总体架构

```
┌────────────────────────────┐      HTTPS / WSS       ┌──────────────────────────────┐
│      抖音 / 快手 客户端        │ ───────────────────▶ │         服务端                 │
│                            │                      │  Node.js 18 + Fastify + ws    │
│  game.js（入口/事件/循环）      │                      │  ├─ REST：登录/上报/榜单/建房   │
│  js/platform.js（双端适配）    │ ◀─────────────────── │  ├─ WS：房间实时对战            │
│  js/engine.js（打字逻辑）      │    下发数据/推送       │  ├─ Redis：房间态/在线/限次/榜   │
│  js/render.js（渲染）         │                      │  └─ MySQL：用户/对局记录        │
│  js/net.js（新增：HTTP+WS）    │                      │                              │
│  js/ad.js（新增：激励视频）      │                      └──────────┬───────────────────┘
│  js/audio.js（新增：音效）      │                                 │ code2Session / 广告回调
│  openDataContext/（新增：好友榜）│                                 ▼
└────────────────────────────┘                 抖音开放平台 / 快手开放平台 / 穿山甲 / 快手联盟
```

### 2.1 客户端新增模块
| 模块 | 职责 |
|------|------|
| `js/net.js` | HTTP 封装（token 注入、错误码）、WebSocket 封装（心跳、重连、消息分发） |
| `js/ad.js` | 激励视频单例：预加载、onClose 判定、失败降级 |
| `js/audio.js` | 音效资源管理：背景循环、一次性音效、音量开关、首次触摸后初始化 |
| `openDataContext/` | 开放数据域：读好友托管数据，渲染 sharedCanvas 好友榜（抖音/快手各自独立目录） |

### 2.2 服务端技术选型
| 组件 | 选型 | 理由 |
|------|------|------|
| 语言/框架 | Node.js 18 + Fastify + `ws` | 与客户端同语言、异步 IO 适合长连接；Fastify 轻量 |
| 实时通道 | WebSocket（WSS） | 双向低延迟；对局进度互推 |
| 缓存/实时态 | Redis（ioredis） | 房间态、在线表、限次计数、排行榜 ZSet |
| 持久化 | MySQL 8（mysql2） | 用户、对局记录、日活统计 |
| 部署 | 抖音云托管 / 快手云 / 腾讯云轻量 | 平台云免运维；**必须 HTTPS/WSS**（两端平台均要求合法证书） |
| 鉴权 | JWT（HS256，有效期 2h） | 无状态、简单；appSecret 只存服务端 |

## 3. 账号与鉴权

### 3.1 登录流程
```
客户端 tt.login()/ks.login() → code
        │
        ▼
POST /api/login { platform, code }
        │
        ▼
服务端 → 调平台 code2Session 换 openid（+session_key/unionid）
        │
        ▼
查 users 表 → 不存在则建号 → 签发 JWT
        │
        ▼
客户端 storage 保存 token，后续请求 Authorization: Bearer <token>
```

- 抖音：`GET https://developer.toutiao.com/api/apps/v2/jscode2session?appid=..&secret=..&code=..` → `{ openid, session_key, unionid? }`
- 快手：`ks.login()` 后走快手小游戏开放平台的 code2Session 接口（**路径以官方最新文档为准**）
- 跨端同号：`users` 表同时存 `tt_openid` / `ks_openid`；平台下发 unionid 时优先用 unionid 关联

### 3.2 用户表（MySQL）

```sql
CREATE TABLE users (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  unionid       VARCHAR(64)  DEFAULT NULL,
  tt_openid     VARCHAR(64)  DEFAULT NULL,
  ks_openid     VARCHAR(64)  DEFAULT NULL,
  nickname      VARCHAR(64)  NOT NULL DEFAULT '',
  avatar_url    VARCHAR(255) NOT NULL DEFAULT '',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_tt (tt_openid),
  UNIQUE KEY uk_ks (ks_openid)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.3 登录接口示意（Node.js）

```js
// routes/auth.js
const jwt = require('jsonwebtoken');
const { JWT_SECRET, TT_APPID, TT_SECRET } = require('../config');

async function login(req, reply) {
  const { platform, code } = req.body;
  const openid = await exchangeOpenId(platform, code);  // 调平台 code2Session
  const user = await upsertUser(platform, openid);
  const token = jwt.sign({ uid: user.id }, JWT_SECRET, { expiresIn: '2h' });
  reply.send({ token, user: { id: user.id, nickname: user.nickname, avatar: user.avatar_url } });
}
```

> 安全约束：`TT_SECRET`/`KS_SECRET` 只存在于服务端环境变量；JWT 密钥独立；客户端不得接触任何密钥。

## 4. 邀请好友实时对战（本期核心）

### 4.1 玩法流程
```
房主：选模式/难度 → 建房 → 分享卡片（query=roomId）
好友：点卡片 → 游戏加载 → 检测启动参数 roomId → 弹出「接受邀请」→ WS 加入房间
双方就绪 → 服务端按 seed 生成同一篇文章下发 → 同时开始
打字进度实时互推（100ms 限频）→ 先打完者胜 → 结算广播 → 双方各自展示/上报
```

### 4.2 房间状态机
```
WAIT（等待加入） → READY（双方已就绪） → PLAYING → FINISHED → CLOSED
      ↑____________________|                    |
      └──────── 对手退出/超时 → 判胜并关闭 ←────┘
```

### 4.3 WS 消息协议（JSON 文本帧）

客户端 → 服务端：
| type | 字段 | 说明 |
|------|------|------|
| `join_room` | roomId | 加入房间 |
| `ready` | - | 就绪 |
| `progress` | typedLen, score, combo, cpm | 进度上报（限 100ms/次） |
| `finish` | typedLen, score, cpm, accuracy, maxCombo | 打完全文 |
| `leave` | - | 离开 |
| `ping` | - | 心跳（10s） |

服务端 → 客户端：
| type | 字段 | 说明 |
|------|------|------|
| `joined` | roomId, opponent | 入房成功 |
| `peer_ready` | nickname | 对手就绪 |
| `game_start` | passage, seed, mode, level, startedAt | 开局（双方同一文本） |
| `peer_progress` | typedLen, score, combo | 对手进度 |
| `peer_finish` | stats | 对手打完全文 |
| `result` | win/lose, stats, roomId | 终局 |
| `peer_left` | reason | 对手离开 |
| `reconnect_ok` | snapshot（双方进度） | 断线重连恢复 |
| `error` | code, msg | 错误 |

### 4.4 服务端房间核心逻辑（示意代码）

```js
// ws/room.js —— 核心：建房/加入/开局/进度/结算（配合 hub.js 做连接注册与鉴权）
const crypto = require('crypto');
const { pickBySeed, CPM_LIMIT } = require('../data/words'); // 服务端词库与客户端同源

const ROOMS = new Map();            // roomId -> room
const LIMIT = { cn: 150, en: 600 }; // 字/分，超人类阈值视为异常

function createRoom(user, { mode, level }) {
  const room = {
    id: crypto.randomBytes(4).toString('hex'),
    mode, level, owner: user.id,
    status: 'WAIT',
    players: new Map(),             // uid -> { conn, ready, typedLen, score, combo, lastReport, finished }
    passage: '', seed: 0, startedAt: 0,
  };
  addPlayer(room, user);
  ROOMS.set(room.id, room);
  return room;
}

function joinRoom(roomId, user) {
  const room = ROOMS.get(roomId);
  if (!room || room.status !== 'WAIT') throw err('ROOM_NOT_AVAILABLE');
  addPlayer(room, user);
  broadcast(room, { type: 'joined', roomId: room.id, opponent: peerOf(room, user) });
  return room;
}

function markReady(room, user) {
  room.players.get(user.id).ready = true;
  broadcast(room, { type: 'peer_ready', nickname: user.nickname });
  if ([...room.players.values()].every(p => p.ready)) startGame(room);
}

function startGame(room) {
  room.seed = Date.now();
  room.passage = pickBySeed(room.mode, room.level, room.seed); // 同 seed 必出同文
  room.status = 'PLAYING';
  room.startedAt = Date.now();
  for (const p of room.players.values()) {
    p.conn.send({ type: 'game_start', passage: room.passage, seed: room.seed,
                  mode: room.mode, level: room.level, startedAt: room.startedAt });
  }
}

function onProgress(room, user, msg) {
  const me = room.players.get(user.id);
  const now = Date.now();
  if (room.status !== 'PLAYING' || me.finished) return;
  if (msg.typedLen < me.typedLen) return;                 // 进度只增不减
  if (now - me.lastReport < 100) return;                  // 100ms 限频
  const cpm = msg.typedLen / Math.max((now - room.startedAt) / 60000, 1 / 60);
  if (cpm > LIMIT[room.mode]) return;                     // 超速 → 忽略并记录
  Object.assign(me, { typedLen: msg.typedLen, score: msg.score, combo: msg.combo, lastReport: now });
  peerOf(room, user).conn.send({ type: 'peer_progress', typedLen: msg.typedLen,
                                 score: msg.score, combo: msg.combo });
  if (msg.typedLen >= room.passage.length) onFinish(room, user, msg);
}

function onFinish(room, user, msg) {
  const me = room.players.get(user.id);
  me.finished = true;
  room.status = 'FINISHED';
  for (const p of room.players.values()) {
    const win = p === me;
    p.conn.send({ type: 'result', win, stats: win ? msg : null,
                  opponentStats: win ? null : msg, roomId: room.id });
  }
  saveRecord(room, me, msg);      // 落 MySQL game_records
  setTimeout(() => ROOMS.delete(room.id), 60_000);
}
```

### 4.5 客户端接入点
- 启动参数读取：`tt.getLaunchOptionsSync().query.roomId`（快手 `ks.getLaunchOptionsSync`，已由 platform.js 收敛）；
  从分享进入且游戏已运行：`tt.onShow(res => res.query)`。
- 分享卡片：`tt.shareAppMessage({ title: '来和我打字对战！', query: 'roomId=' + roomId })`。
- 对局中键盘照常使用系统键盘；收到 `game_start` 后由 engine 接管（与单机共用打字判定，仅进度上报走 net.js）。

### 4.6 公平性与防作弊
| 手段 | 说明 |
|------|------|
| 同 seed 同文本 | 文章由服务端生成下发，双方完全一致 |
| 进度只增不减 + 100ms 限频 | 防连发刷屏 |
| CPM 阈值 | 中文 ≤150 字/分、英文 ≤600 字/分（可调），超限忽略并计数 |
| 异常累计 | 单局异常 3 次直接判负；日异常 N 次进观察名单 |
| 对局录像 | 二期：关键事件序列落库，供申诉回溯 |

> 说明：打字判定保留在客户端（本地即时手感），服务端做"进度可信度校验"，这是快节奏打字游戏的主流折中。若后续要严格防外挂，再升级为服务端权威判定。

### 4.7 断线重连
- 心跳 10s / 超时 30s 判定离线；房间保留 60s（Redis TTL）。
- 重连：携带 token + roomId 恢复会话，服务端补发 `reconnect_ok`（双方当前 typedLen/score 快照）。
- 离线超过 60s：对手判胜，房间关闭。

## 5. 好友排行榜

### 5.1 方案对比（结论：好友榜用开放数据域，全局榜用服务端）
| 维度 | 开放数据域（好友榜，免服务器） | 服务端排行榜（全局/赛季榜） |
|------|------------------------------|------------------------------|
| 数据来源 | 平台关系链 + 用户托管 KV | 服务端对局记录 |
| 延迟 | 即时（平台直连） | 网络往返 |
| 成本 | 0 | 服务器 + Redis |
| 范围 | 仅本平台内好友 | 全服 / 跨端 |
| 双端互通 | 不通（抖音好友 ≠ 快手好友） | **可互通**（同一 userId） |
| 建议 | 首页/结算页"好友榜"主方案 | 全局榜、赛季榜（二期） |

### 5.2 开放数据域（主方案，免服务器）
```
主域（每局结算后）：
  tt.setUserCloudStorage({ keyValueData: [{ key: 'best',
    value: JSON.stringify({ score, cpm, rank }) }] })

开放数据域 openDataContext/index.js：
  tt.getFriendCloudStorage({ keyList: ['best'] })
  → 排序 → 绘制到 sharedCanvas
主域：
  tt.getOpenDataContext().postMessage({ type: 'render_best' })
  → 把 openDataContext 的 canvas 显示在榜单区域
```

约束与注意：
- 开放数据域**只能操作自己的 Canvas（sharedCanvas）**，不能碰主域画布/DOM；主域做"窗口"，开放域画内容。
- 托管 KV 每用户配额约 1MB、key 数有限，只存精简字段（score/cpm 字符串即可）。
- 快手 API 同构（`ks.setUserCloudStorage` / `ks.getFriendCloudStorage`），但**两端数据互不相通**——若产品要求跨端好友榜，只能走服务端。

### 5.3 服务端排行榜（全局榜，二期）
- 存储：`Redis ZSet` `lb:{mode}:{level}`，value=userId，score=最高分（或最高 cpm，产品定）；每日/每周快照落 MySQL 做历史榜。
- 接口：
  - `GET /api/leaderboard?mode=&level=&limit=50` → `{ list: [{rank, nickname, avatar, score, cpm}], mine: {rank, score} }`
  - 上榜时机：结算后异步上报（`POST /api/records`），避免阻塞对局。

## 6. 激励视频复活

### 6.1 触发点设计（产品建议，可调）
| 场景 | 触发 | 奖励 | 限制 |
|------|------|------|------|
| 单机·失败 | 结算页按钮「看广告复活」 | 复活继续本局，AI 进度回退至 60% | 每局限 1 次 |
| 单机·决胜 | AI 进度 ≥80% 弹窗 | 对手暂停 5 秒 | 每局限 1 次 |
| 对战·失败 | 结算页「看广告再战」 | 与同一好友免费再来一局 | 每天限 3 次 |
| 对战·中途 | 落后对手 ≥40% 弹窗（可选） | 本局暂停对手 5 秒 | 每局限 1 次 |

### 6.2 客户端接入（js/ad.js 示意，双端同构）

```js
// js/ad.js —— 激励视频单例
let ad = null;
function getRewardedAd(adUnitId) {
  if (ad) return ad;
  ad = Platform.api.createRewardedVideoAd({ adUnitId });
  ad.onClose(res => {                       // 只看 isEnded
    if (res && res.isEnded) onAdComplete();
    else Platform.toast('完整看完广告才能获得奖励哦');
  });
  ad.onError(() => { Platform.toast('广告加载失败，请稍后再试'); });
  return ad;
}
function showAd() { getRewardedAd(CONFIG.AD_REVIVE).show().catch(() => ad.load().then(() => ad.show())); }
```

### 6.3 服务端校验与限频（防刷）
```
客户端看完广告 → POST /api/revive/confirm { scene }
服务端：
  1) 限次：Redis INCR revive:day:{uid}，TTL 至次日零点；超过上限拒绝
  2) 对局内限次：房间内存计数
  3)（进阶）广告服务端回调：抖音/快手可将「播放完成」事件回调到服务端配置地址（带签名），
     服务端验签后再发奖 —— 需要企业主体 + 广告平台配置，上线前按平台文档接入
```
- MVP 口径：客户端 `isEnded` + 服务端限次即够用；用户量起来、被刷后再接服务端回调。
- 广告位：抖音 → 穿山甲后台申请 `adUnitId`；快手 → 快手联盟申请。**接入广告需企业主体并完成认证**。

## 7. 音效（纯客户端，本期最快落地）

### 7.1 资源规划（`audio/` 目录）
| 文件 | 用途 | 建议 |
|------|------|------|
| `bgm.mp3` | 背景音乐 | 循环，≤1MB，音量 0.4 |
| `tick.mp3` | 击键正确 | 短促，≤50KB |
| `error.mp3` | 打错 | 短促 |
| `win.mp3` / `lose.mp3` | 结算 | ≤200KB |
| `click.mp3` | 按钮 | 短促 |
| `combo.mp3` | 连击 ≥5 | 短促 |

包体注意：小游戏主包约 4MB（抖音/快手规则相近，以最新文档为准），音效总量控制在 **≤1.5MB**；超出部分改用远程 URL（`createInnerAudioContext({ src: 'https://cdn...' })`，需配置下载域名白名单）。

### 7.2 客户端接入（js/audio.js 示意）
```js
// js/audio.js —— 统一音效管理
const sounds = {};
function init() {           // 首次触摸后调用（平台 autoplay 限制）
  if (sounds.bgm) return;
  sounds.bgm = Platform.api.createInnerAudioContext();
  sounds.bgm.src = 'audio/bgm.mp3'; sounds.bgm.loop = true; sounds.bgm.volume = 0.4;
  ['tick', 'error', 'win', 'lose', 'click', 'combo'].forEach(k => {
    sounds[k] = Platform.api.createInnerAudioContext();
    sounds[k].src = 'audio/' + k + '.mp3';
  });
}
function play(name) { if (sounds[name]) sounds[name].play(); }
```
- 播放时机：engine 内正确/错误/结算处调用 `audio.play('tick'/'error'/'win'…)`，错误同时 `Platform.vibrateShort()`。
- 设置项：全局音效开关（存 storage），双端 API 名差异由 platform.js 收敛（`tt.setInnerAudioOption` / `ks.setInnerAudioOption` 均支持 mixWithOther/obeyMuteSwitch）。

### 7.3 版权合规
音效/音乐需使用**可商用素材**（爱给网、耳聆网 CC0、自行合成等），避免审核与侵权风险；README 记录素材来源与授权。

## 8. 数据表设计（MySQL DDL）

```sql
-- 对局记录（单机 + 对战统一落这里）
CREATE TABLE game_records (
  id           BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id      BIGINT UNSIGNED NOT NULL,
  room_id      VARCHAR(16)  DEFAULT NULL,          -- 对战场次
  mode         VARCHAR(8)   NOT NULL,              -- cn | en
  level        VARCHAR(8)   NOT NULL,              -- easy | normal | hard
  result       VARCHAR(8)   NOT NULL,              -- win | lose | ai_win ...
  score        INT          NOT NULL DEFAULT 0,
  cpm          INT          NOT NULL DEFAULT 0,
  accuracy     INT          NOT NULL DEFAULT 0,
  max_combo    INT          NOT NULL DEFAULT 0,
  passage_hash CHAR(32)     NOT NULL,              -- 文章指纹，防题库被改
  created_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_user (user_id, created_at),
  KEY idx_mode (mode, level, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 复活记录（防刷审计）
CREATE TABLE revive_logs (
  id         BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id    BIGINT UNSIGNED NOT NULL,
  scene      VARCHAR(16) NOT NULL,                 -- revive | slow_down | rematch
  order_id   VARCHAR(64) DEFAULT NULL,             -- 广告回调订单号（进阶）
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_user_day (user_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 双端 API 行为差异（键盘/广告/开放域） | 功能双端不一致 | 全部收敛 platform.js；双端真机回归矩阵 |
| 中文输入法组词串入输入框 | 对局误判 | 已做拼音串过滤；对战默认双方同模式，体验一致 |
| 开放数据域配额/机型兼容 | 好友榜异常 | 只存精简字段；降级为服务端榜 |
| 对局同步延迟 | 观感卡顿 | 进度 100ms 限频 + 客户端本地插值 |
| 外挂/脚本打字 | 排行榜污染 | 服务端 CPM 阈值 + 限频 + 异常计数封禁 |
| 服务器成本 | 亏损 | 起步单机小实例 + 云 Redis 基础版；按量扩容 |
| 广告回调配置复杂 | 发奖不可控 | MVP 用客户端 isEnded + 服务端限次，稳定后再接回调 |

### C. 排行榜（services/leaderboard.js）

```js
const redis = require('../db/redis');
const KEY = (mode, level) => `lb:${mode}:${level}`;

async function submitScore(userId, { mode, level, score, cpm }) {
  const zkey = KEY(mode, level);
  const cur = await redis.zscore(zkey, String(userId));
  if (!cur || score > Number(cur)) {                 // 只取最高分
    await redis.zadd(zkey, score, String(userId));
    await redis.set(`lb:meta:${userId}:${zkey}`, JSON.stringify({ score, cpm }));
  }
}

async function getTop(mode, level, limit) {
  const zkey = KEY(mode, level);
  const rows = await redis.zrevrange(zkey, 0, limit - 1, 'WITHSCORES');
  return rows;  // [{userId, score}] → 再批量查昵称头像
}
```

### D. 复活限次（routes/revive.js）

```js
const DAY_LIMIT = 5;
async function confirmRevive(req, reply) {
  const { uid } = req.user;
  const key = `revive:day:${uid}`;
  const n = await redis.incr(key);
  if (n === 1) await redis.expire(key, secondsUntilMidnight());
  if (n > DAY_LIMIT) return reply.code(429).send({ code: 'REVIVE_LIMIT' });
  // 落 revive_logs，记录 scene（orderId 占位）
  return reply.send({ ok: true, remain: DAY_LIMIT - n });
}
```
