# 打字比赛 · 产品文档

> 版本：V1.0（可玩版本已交付）　｜　平台：抖音小游戏 + 快手小游戏（一套代码双端发布）
> 代码位置：`typing-race/`　｜　技术方案：`docs/技术方案.md`

---

## 一、产品概述

**一句话定位**：一款「打字竞速」轻竞技小游戏——玩家照着屏幕上的文章逐字敲击，与 AI 对手或真实好友比谁先打完，用速度、连击和段位获得即时成就感。

| 项目 | 说明 |
| --- | --- |
| 品类 | 休闲竞技 / 打字练习 / 轻社交对战 |
| 单局时长 | 20–60 秒（符合小游戏「短平快」节奏） |
| 上手成本 | 零门槛，会打字就能玩；3 秒内进入第一局 |
| 核心爽点 | 实时进度对比、连击加成、段位评级、输赢只差一点的翻盘感 |
| 变现方式 | 激励视频（复活/减速/再战）+ 后续可接入插屏与内购皮肤 |

---

## 二、目标用户与使用场景

**核心用户**
1. 学生群体：想练打字速度、和同学比拼（中文/英文双题库）。
2. 上班族碎片时间：通勤、午休来一局 30 秒的竞速。
3. 亲子/家庭场景：家长带孩子练英文单词打字（简单档位文章短、词汇常见）。

**典型场景**
- 场景 A：刷到分享卡片 → 点进即入房 → 和老友同文竞速 → 输赢后看广告复活/再战 → 分享战绩再来一轮。
- 场景 B：独自打开 → 选中文/英文 + 难度 → 打一局 → 拿段位 → 冲「我的最高分」。
- 场景 C：连输两局 → 出现「看广告让对手暂停 5 秒」→ 用策略翻盘。

**需求洞察**
- 打字类产品天然有「可量化进步」属性（CPM、正确率、段位），适合做留存钩子。
- 小游戏社交裂变的核心是「不服再来一局」，因此对战与再战链路必须极短。

## 三、核心玩法

### 3.1 单机竞速（AI 对战）
1. 首页选择 **语种**（中文 / 英文）与 **难度**（简单 / 普通 / 困难）。
2. 系统随机抽取一篇文章，玩家与 AI 对手同时起跑。
3. 逐字输入正确则推进；输错则该字符闪红、震动、输入框清空，需重新输入（错误计入正确率）。
4. 先打完全文者获胜；胜利后进入结算，展示得分、CPM、正确率、最高连击、段位。

**AI 强度设计（按文章长度折算，保证「努努力就能赢」）**

| 难度 | AI 打完一篇文章的耗时 | 体感 |
| --- | --- | --- |
| 简单 | 25 秒 | 新手也能赢，建立信心 |
| 普通 | 32 秒 | 需正常打字速度 |
| 困难 | 42 秒 | 需要较快且少失误 |

> AI 速度 = 文章字数 / 对应耗时，进度条实时可视化，形成「追赶感」。

### 3.2 好友对战（实时 PVP）
1. 首页点「好友对战」→ 服务端建房，生成 **6 位房间号**。
2. 点「邀请好友」→ 生成分享卡片（携带 `roomId`），好友点击卡片直接入房。
3. 双方点「就绪」→ 服务端下发**同一篇文章**（按种子生成，保证绝对公平）→ 倒计时开打。
4. 对局中每隔 120ms 上报一次进度，双方能看到对手的实时进度条与连击。
5. 先打完者上报完成 → **服务端统一判定胜负**（防作弊，客户端不自行判胜）。
6. 断线 60 秒内可重连回房，超时判离线方失败。

### 3.3 翻盘与复活（激励视频三场景）

| 场景 | 触发时机 | 奖励 | 限制 |
| --- | --- | --- | --- |
| 失败复活 | 单机输给 AI | AI 进度回退至 60%，继续打 | 每日 5 次（服务端校验，防刷） |
| 对手减速 | 对局中 AI 进度 ≥ 80% | AI 暂停 5 秒 | 每局 1 次 |
| 对战再战 | PVP 输了 | 重新开局（新文章） | 每日 5 次（与复活共享额度） |

> 广告必须**完整看完**（`onClose.isEnded === true`）才发奖励，中途关闭不给，防作弊。
> 服务端不可用时客户端有本地每日限次兜底（仍可玩，不阻断体验）。

### 3.4 音效
- 6 类音效：按键 `tick`、错误 `error`、点击 `click`、连击 `combo`、胜利 `win`、失败 `lose`，另有轻量 BGM。
- 首次触摸后初始化音频（规避小游戏 autoplay 限制）；首页可一键静音，状态本地持久化。

### 3.5 好友排行榜
- 使用小游戏**开放数据域**（`openDataContext`）拉取微信/抖音/快手关系链好友数据，展示好友最高分排名。
- 每局结算后通过 `setUserCloudStorage` 上报 `best` 分数（托管数据，跨端一致）。
- 另提供**全局榜**（服务端 MySQL 聚合，按语种+难度分榜），展示我的排名。

## 五、界面与交互

### 5.1 首页
- 顶部：标题 + 最高分
- 中部：语种切换（中文/英文）、难度切换（简单/普通/困难）
- 主按钮：**开始比赛**（大按钮，拇指热区）
- 次按钮：好友对战 / 好友排行榜 / 全局榜
- 右上角：音效开关

### 5.2 对战页
- 顶部：AI/对手头像 + 昵称 + 进度条（与我的进度条上下对照）
- 中部：文章区（已打对的字高亮，当前字有光标，错误闪红）
- 底部：实时 CPM、连击数、正确率
- 特殊：AI 进度 ≥80% 时浮出「看广告让对手暂停 5 秒」按钮

### 5.3 结算页
- 胜/负大标题 + 得分
- 四项指标：CPM、正确率、最高连击、段位
- 按钮：看广告复活（负）/ 再来一局 / 分享战绩 / 返回首页
- PVP：看广告再战 / 返回首页 / 分享战绩

### 5.4 对战大厅
- 房间号 + 「邀请好友」分享按钮
- 双方头像/昵称 + 就绪状态
- 按钮：邀请好友 / 就绪 / 离开（等宽三键，无重叠热区）

## 六、数值与规则

### 6.1 计分
- 每打对一个字符：`+10 + min(连击, 50)` 分（连击越高单字收益越高，鼓励零失误）。
- 胜利额外加成（结算页体现总分红字）。
- 段位按 CPM 评定：

| 段位 | 英文 CPM | 中文 CPM |
| --- | --- | --- |
| S | ≥300 | ≥120 |
| A | ≥225 | ≥90 |
| B | ≥150 | ≥60 |
| C | ≥100 | ≥36 |
| D | <100 | <36 |

### 6.2 题库
- 中文：短句/诗意文案，30 篇左右，按难度分层。
- 英文：常用短语/谚语/单词流，30 篇左右，按长度分层。
- 服务端持有同一份题库（`server/src/words.js`），对战时按种子下发，保证双端同文。

### 6.3 限次与防刷
- 复活/再战：每日 5 次，服务端按「用户+场景+日期」计数，超限返回 429。
- 进度上报：客户端 120ms 限频；服务端对异常高频/异常进度做丢弃处理。
- 判胜：仅服务端判（比对双方完成时间与进度），客户端不可自判。

## 七、变现设计

**主变现：激励视频（三处）**
1. 失败复活 —— 最高频场景，用户付费意愿强（不想输）。
2. 对手减速 —— 对局中即时钩子，转化路径最短。
3. 对战再战 —— 社交场景，输给好友后不服气，转化率高。

**设计要点**
- 广告只在「用户已有损失感」时出现（输了/快输了），不做打断式弹窗。
- 每次激励都能立刻改变局面（AI 回退 / 暂停 / 重开），价值可感知。
- 每日限次既控体验又防刷量，后续接入广告服务端回调验签后可放开。

**后续变现扩展**
- 插屏：局间自然切换时展示。
- 皮肤/主题：文章字体、背景、光标样式。
- 会员：免广告 + 专属题库 + 高级段位徽章。

## 九、双端发布

| 环节 | 抖音小游戏 | 快手小游戏 |
| --- | --- | --- |
| 项目配置 | `project.config.json`（填 tt appid） | `kuaishou.project.config.json`（填 ks appid） |
| 平台 API | `tt.*` | `ks.*`（兼容层自动识别） |
| 广告 | 穿山甲激励视频（填 adunit） | 快手联盟（填 adunit） |
| 域名 | 需在开发者后台配置 HTTPS/WSS 合法域名 | 同上 |
| 开放数据域 | 抖音关系链 | 快手关系链（API 名一致） |

**发布步骤**
1. 替换 `js/config.js` 中 `SERVER_BASE` 与三个广告位 ID。
2. 部署服务端（HTTPS/WSS，见技术方案）。
3. 开发者工具导入对应配置 → 真机预览 → 提审。
4. 提审材料：类目（休闲游戏）、隐私政策（含关系链/广告说明）、版号说明（如涉及）。

## 十、服务端与接口

**技术栈**：Node.js + 内置 HTTP/WS（零外部依赖，可直接跑）+ 生产建议 MySQL/Redis

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/login` | POST | 平台 code 换 token |
| `/api/rooms` | POST | 建房，返回 roomId |
| `/api/records` | POST | 上报单局成绩（全局榜数据源） |
| `/api/leaderboard` | GET | 全局榜（mode + level 分榜） |
| `/api/revive/confirm` | POST | 复活/再战限次校验（超限 429） |
| `/ws` | WS | 认证 → 入房 → 就绪 → 开局 → 进度 → 完成 → 判胜 → 再战 |

**WS 消息**
- 客户端→服务端：`auth` / `join_room` / `ready` / `progress` / `finish` / `rematch` / `leave` / `ping`
- 服务端→客户端：`joined` / `peer_joined` / `peer_ready` / `game_start` / `peer_progress` / `peer_finish` / `result` / `peer_left` / `peer_rematch` / `error` / `pong`

## 十一、数据埋点与运营指标

**核心指标**
| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 次留 | 次日回访率 | ≥35% |
| 单局完成率 | 开局→结算占比 | ≥80% |
| 人均局数 | 日人均对局 | ≥6 局 |
| 广告渗透 | 看激励视频用户占比 | ≥30% |
| 分享率 | 分享卡片/战绩用户占比 | ≥10% |
| 好友对战占比 | PVP 局数 / 总局数 | ≥20% |

**建议埋点事件**
`app_launch` / `game_start` / `game_finish`(含 win、cpm、rank) / `ad_show` / `ad_complete` / `revive_use` / `pvp_create` / `pvp_join` / `pvp_finish` / `share_click` / `leaderboard_view`

## 十二、风险与合规

| 风险 | 应对 |
| --- | --- |
| 广告刷量（脚本狂看复活） | 服务端每日限次 + 后续接广告平台服务端回调验签 |
| 对战作弊（客户端自判胜） | 以服务端判胜为准，客户端仅作展示 |
| 跨端公平性 | 服务端同种子下发同一文章，双端题库一致 |
| 关系链隐私 | 仅通过开放数据域读取，不落库、不外传 |
| 断线体验 | 60 秒重连窗口 + 超时判负 + 提示 |
| 内容合规 | 题库无敏感内容；上线前走平台内容审核 |
| 域名/证书 | 必须 HTTPS/WSS 且已备案，否则小游戏无法请求 |
